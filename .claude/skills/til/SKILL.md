# TIL 글 만들기

사용자가 준 주제나 대화 내용을 바탕으로 짧은 TIL 글을 만든다. 목표는 10분 안에 발행할 수 있는 글이다.

## 절차
1. 주제를 한 문장 제목으로 다듬는다. 배운 결과가 드러나야 한다. (예: "Vitest 브라우저 모드는 jsdom과 이벤트 순서가 다르다")
2. 슬러그를 만든다: 영문 소문자 kebab-case, 5단어 이하. 한글 제목이면 핵심 영어 키워드로.
3. 오늘 날짜로 `src/content/posts/<YYYY>/<slug>.md` 를 만든다. 같은 이름이 있으면 `-2`를 붙인다.
4. 태그는 기존 태그를 우선 재사용한다. `grep -rh "^tags:" src/content/posts --include=*.md | sort | uniq -c | sort -rn | head -30` 으로 확인. 3개 이하, 소문자 kebab-case.
5. 본문 구조:
   - 첫 문단: 무엇을 하다가 무엇에 막혔는지 (2~3문장)
   - `## 원인` 또는 `## 알게 된 것`
   - `## 해결` (코드가 있으면 최소 재현만, 언어 명시)
   - 필요하면 `## 참고` 에 링크
6. `npm run build` 로 빌드가 통과하는지 확인하고, 만든 파일 경로와 예상 주소(`/posts/<YYYY>/<slug>/`)를 알려준다.

## 말투 (쓰기 전에 반드시)

**본문을 쓰기 전에 `WRITING.md` 의 「말투」 절을 읽는다.** 2019년 글 168편을 세어서 뽑은 규칙이라 추측으로 대체하지 않는다. 핵심만 옮기면:

- 평서체 "~다"만. 존댓말 없음. 개념은 현재형("~한다", "~이다"), 내가 한 일은 과거형("~했다").
- 문장 중앙값 61자. 접속사로 문장을 시작하지 않는다("그래서", "하지만"은 168편에 0회). 연결은 문장 안에서 "즉", "따라서", "대신"으로.
- 반응은 사실 바로 옆에 한 문장. 따로 문단을 만들지 않는다. 느낌표는 문단당 하나까지.
- 볼드는 문장을 통째로. 불릿이 번호목록보다 4배 많다.
- 마무리 소제목("정리", "앞으로", "느낀 점")을 붙이지 않는다. 내용이 끝나면 글도 끝난다.

감이 안 잡히면 `src/content/posts/2019/` 에서 TIL 두세 편을 열어 실제 문장을 보고 맞춘다.

## 지키기
- 사용자가 말하지 않은 사실을 지어내지 않는다. 모르면 `<!-- TODO: 확인 -->` 주석을 남긴다.
- 막혔던 얘기를 빼지 않는다. 잘 풀린 것만 쓰면 이 블로그의 글이 아니다.
- frontmatter 형식은 CLAUDE.md 의 예시를 따른다.
